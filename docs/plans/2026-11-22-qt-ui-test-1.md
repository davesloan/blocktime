# Qt UI Test 1 (Qt Shell and Live Data) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, per CLAUDE.md / D-033; no
> subagent-driven development). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Qt 6 + QML window that runs the real recorder on its own thread and shows live flight data and block
events, in a dark, polished style. Dave can fly a real flight with it instead of the console recorder and judge
the four pass criteria in `docs/qt-ui-test-context.md`.

**Architecture:**
- The recorder's main loop moves out of `main.cpp` into a plain C++ `Recorder` class in a new `blocktime-sim`
  library (with `sim_connection.cpp`). It reports to an observer interface and knows nothing about Qt.
- The console recorder keeps working: its `main.cpp` becomes a thin wrapper with a console observer that prints
  the same lines as today.
- The Qt app (`blocktime-app`) runs `Recorder::run()` on a `std::jthread`. Its observer posts each update to a
  `RecorderBridge` QObject on the GUI thread. QML only displays what the bridge exposes. This follows the context
  doc's rule: logic in plain C++, QML only displays.
- In debug builds, QML is read from the source folder and reloads when a file is saved, so a UI change shows
  without a rebuild.
- **Layout (Dave, D-052):** everything goes in the existing `recorder/` project. The new C++ files sit in
  `recorder/src/` next to the recorder code, and the QML files go in `recorder/qml/`. On the branch, Qt becomes a normal requirement of
  that one build. If Qt wins, this one project becomes the whole app, and the repo root layout gets sorted out at
  merge time.

**Tech Stack:** C++20, MSVC /W4, CMake presets + Ninja, vcpkg (nlohmann-json, gtest), SimConnect (MSFS 2020 SDK),
Qt 6.12.0 (msvc2022_64 kit, official installer): Qt Quick, Qt Quick Controls (Basic style).

**Spec:** `docs/qt-ui-test-context.md` (UI test 1, pass criteria), D-050, D-051. Recorder behaviour:
`docs/recorder.md`, D-037, D-046..D-049.

## Choices made here (logged as Proposed in Task 5)

- **D-052, where the app lives (Dave):** in the recorder project itself. The new C++ files go in `recorder/src/`
  and the QML in `recorder/qml/` (next to `src/` and `tests/`). `blocktime-app` is one more target in
  `recorder/CMakeLists.txt`. On the branch,
  Qt is always required, and the existing presets build it. Qt is found through the cache variable
  `BLOCKTIME_QT_DIR` (default `C:/Qt/6.12.0/msvc2022_64`, or `%BLOCKTIME_QT_DIR%` if set), which is appended to
  `CMAKE_PREFIX_PATH`. It works like `SIMCONNECT_SDK_DIR`. The console recorder stays as a second target during the
  test, as a fallback for real flights. Why: if Qt wins there is one app and one build, so the test is built
  that way from the start and can merge as it is. Alternatives considered: an `app/` subfolder of `recorder/`, or a
  top-level `app/` with its own build.
- **D-053, the recorder loop as a library:** `Recorder` + `RecorderObserver` in `recorder/src/recorder.{h,cpp}`.
  Together with `sim_connection.cpp` and a `single_instance.{h,cpp}` helper, it forms the static library
  `blocktime-sim` (it needs SimConnect and `windows.h`, so it can't go in `blocktime-core`, D-041). Why: one copy of the
  loop, so the app's log is exactly the recorder's log. Copying the loop into the app was the alternative.
- **D-054, QML style and theme:** Qt Quick Controls **Basic** style, the only built-in style that can be fully
  re-skinned. A `Theme` QML singleton holds every colour, size and font. The font is **Segoe UI Variable**
  (Windows 11 system font, nothing to bundle) with tabular figures (`font.features: { "tnum": 1 }`) so numbers
  don't jitter. The window title bar goes dark through `QStyleHints::setColorScheme(Qt::ColorScheme::Dark)`.
- **D-055, QML hot reload in debug:** in debug builds, a `QQmlAbstractUrlInterceptor` maps the module's
  `qrc:/qt/qml/BlockTime/qml/*.qml` URLs to the files in `recorder/qml/`. A `QFileSystemWatcher` on the source folder then calls
  `clearComponentCache()` and reloads `Main.qml` on save. The recorder thread and the bridge keep running
  through a reload. Release builds use the compiled QML in the exe only. Why: the change → see-it loop is a pass
  criterion, and this needs no Qt Creator. Qt Creator's QML Preview was the alternative.
- **D-056, running from the build folder:** a POST_BUILD step runs `windeployqt` on `blocktime-app.exe`, so the
  exe runs from `build\x64-*\` without Qt on PATH. It uses `--qmldir`, `--no-translations`,
  `--no-system-d3d-compiler` and `--no-opengl-sw`.

## Review Focus

Failure modes that this build's tests don't cover, most likely first. Each has a check in the task that
owns it:
1. **Closing the window during a flight** must log `flight_interrupted` (`recorder_exit`) and `recorder_stopped`,
   just like Ctrl+C. It must not just kill the thread. → Task 3 smoke check; Task 6 sim step.
2. **Starting the app while the console recorder runs** (or the other way round) must refuse to record, and the
   app must say why on screen. → Task 3 smoke check.
3. **Console recorder unchanged** after the loop moves out. The D-048 smoke run (a lone `block_out` in a temp
   log folder) must print and log exactly what it did in 0.3.0. → Task 1 Step 6.
4. **A QML error during hot reload** (typo, then save) must not crash the app or stop the recorder. The window
   comes back on the next good save. → Task 4 Step 5.
5. **Updates from the recorder thread** must reach QML only through queued calls to the GUI thread. A direct call
   could crash later at random. → Task 3 Interfaces (the observer never touches the bridge directly).

- Produces (in `namespace blocktime`):
  ```cpp
  enum class ConnectionState { WaitingForSim, SimStarting, Connected };

  class RecorderObserver {
  public:
      virtual ~RecorderObserver() = default;
      virtual void onLine(const std::string& line, bool error) = 0;  // every console line except telemetry;
                                                                     // error = it went to stderr (LOST:)
      virtual void onConnection(ConnectionState state) = 0;
      virtual void onTelemetry(const TelemetrySample& s) = 0;     // valid samples only, after they're logged
      virtual void onBlockEvent(const BlockEvent& e) = 0;         // after the outbox has taken it
  };

  class Recorder {
  public:
      Recorder(std::filesystem::path logDir, RecorderObserver& observer);
      // Runs until `stop` is true, then closes cleanly (sim.close, endSession, outbox flush, recorder_stopped).
      // Returns 0, or 1 if recorder_started couldn't be written (as main returns today).
      int run(const std::atomic<bool>& stop);
      const std::filesystem::path& logDir() const;
  };

  // Holds Local\BlockTimeRecorder for the life of the object (D-037).
  class SingleInstance {
  public:
      SingleInstance();
      bool acquired() const;
  };
  ```

  (unchanged).

### Task 3: Recorder on its own thread, exposed to QML

**Files:**
- Create: `recorder/src/recorder_bridge.h`, `recorder/src/recorder_bridge.cpp`
- Create: `recorder/src/event_feed_model.h`, `recorder/src/event_feed_model.cpp`
- Modify: `recorder/src/app_main.cpp`, `recorder/CMakeLists.txt`

**Interfaces:**
- Consumes: `Recorder`, `RecorderObserver`, `ConnectionState`, `SingleInstance` (Task 1).
- Produces `class RecorderBridge : public QObject` (`QML_ELEMENT`, `QML_UNCREATABLE`), given to `Main.qml` as
  `required property RecorderBridge recorder` through `engine.setInitialProperties`. It has read-only `Q_PROPERTY`s,
  each with a `NOTIFY`:
  - `QString connection`: `"waiting"`, `"starting"`, `"connected"`, or `"blocked"` (another recorder holds the
    mutex)
  - `QString logDir`
  - `bool hasSample`, `double altitudeFt` (indicated), `double iasKt`, `double gsKt`, `double vsFpm`, `double fuelLb`
  - `bool parkingBrake`, `bool onGround`, `int enginesRunning`, `int engineCount`, `QString aircraft` (title),
    `QString atcId`
  - `bool flightOpen`, `QDateTime blockOutTime`, `double blockOutFuelLb`, `QString lastFlightSummary` (e.g.
    `"Block in 1:42 · 15,517 → 9,804 lb"` or `"Interrupted (sim_stopped)"`)
  - `EventFeedModel* events`
  - `Q_INVOKABLE void openLogFolder()` (`QDesktopServices::openUrl`)
- `class EventFeedModel : public QAbstractListModel` with roles `time` (`"HH:mm:ss"` UTC), `kind` (`"block"`,
  `"warn"` or `"info"`) and `text`. Newest first, capped at **200** rows.
- **Threading rule (Review Focus 5):** the app's `BridgeObserver` (in `recorder_bridge.cpp`) is called on the
  recorder thread. It copies what it gets and calls `QMetaObject::invokeMethod(bridge, lambda,
  Qt::QueuedConnection)`. It never reads or writes bridge members itself. `onLine` with `error` set, or with text
  starting `WARNING`, gets kind `"warn"`. Block events get `"block"`, and the rest get `"info"`.

- [ ] **Step 1: Thread lifetime.** `app_main.cpp` makes a `SingleInstance`. If it isn't acquired, the bridge's

  and `join()`, so the clean close runs before the bridge is destroyed (Review Focus 1). The app takes the same
  `--log-dir <folder>` argument as the recorder.
- [ ] **Step 2: Implement the bridge and the model** as above. A block event sets `flightOpen` and
  `blockOutTime`/`blockOutFuelLb` (from `BlockOut`), or clears them and sets `lastFlightSummary` (from `BlockIn` /
  `FlightInterrupted`).
