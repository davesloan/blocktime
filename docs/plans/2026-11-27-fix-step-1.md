# Fix step 1: protect what can't be undone

Step 1 of the technical review's fix order (`docs/reviews/2026-11-27-technical-review.md`, D-225). Every item is
small. Each fix gets a failing test first where it can be tested without the sim (D-174: money and history keep
careful tests).

## Tasks

1. **Separate data for development (1.1).** One data folder for everything (`dataDir()`; the event log, settings,
   database, config files, tiles and errors.log all live under it).
   - `--data-dir <folder>` sets it.
   - The debug build defaults to `%LOCALAPPDATA%\BlockTime-dev`, seeded once from the real folder (the database through
     `VACUUM INTO`, the config files and settings copied, the event logs copied).
   - `--demo` and `--grab` run on a scratch copy in `%TEMP%` (same seeding, but read the source's event logs in place),
     don't start the recorder and don't take the mutex.
2. **Backup before migrating (part of 1.5).** `openAirlineDatabase` writes `blocktime.before-schema-N.db` with
   `VACUUM INTO` before running any pending migration on an existing airline, and refuses to migrate if it can't.
3. **Flown but not settled (1.2).** Cancel is refused when the log shows the planned flight was flown, or a block in
   was seen and the flight hasn't settled. The notice says "Flown, waiting to settle: …". A pending settle is retried
   on the minute tick. `findFlownFlight` reads every log file from the planned flight's day on, not the last 7.
4. **Check the transaction after the debrief savepoint (1.3).** `ROLLBACK TO` and `RELEASE` results are checked, and
   settlement fails if the transaction is no longer open. Test: a temp trigger that rolls back the transaction from
   inside `writeMeasurements`; no ledger line may survive.
5. **Read errors aren't $0 (1.4).** `cashCentsAsOf`, `fleetSize` and `hoursFlown` report errors; `settleLeases` aborts
   on any of them. At start and on the tick, flights settle before leases.
6. **Tolerant JSON readers (1.6, 3.4 small part).** One header of readers that give the fallback for null, missing or
   wrong-typed fields; used by the debrief measurement and the in-flight panel. A measurement error is logged to
   errors.log. The bridge dumps with `replace`; the GUI-thread event handlers and the recorder thread catch exceptions
   and log them instead of terminating.
7. **Flight events through the outbox (1.7).** Every event carrying a `flight_id` (flight events, cockpit, the app's
   events) goes through the outbox, so a failed write is held and retried like a block event.
8. **Recorder health outside `--dev` (1.8).** The bridge has a `recorderProblem` text, shown in Live's banner: events
   held, or the log folder can't be written. The recorder retries opening the log every 5 s instead of giving up.
9. **Confirm closing mid-flight (1.9).** While a flight is open, closing the window asks first.
10. **Event log round trip (1.10, 6.1).** An `EventLog` test in a temp folder: write, tear the tail, write again, read
    back through `findOpenFlight`, `findFlownFlight` and `loadFlightEvents`. Settlement tests build their block lines
    with `toJson(BlockEvent)`. The real-log settle test checks the money, fuel in, arrival and block time.
11. **ATC review keeps the last copy (1.11); `secondsUntil` stops at the window's end (1.12).**

Then: build debug and release with no warnings, qmllint clean, all tests pass; check the app with `--demo` and `--grab`;
code review; docs (decisions, progress, README's Run section for `--data-dir` and the dev folder, recorder.md for the
outbox); commit and push.
