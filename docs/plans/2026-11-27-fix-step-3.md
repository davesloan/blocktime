# Fix step 3: groundwork for dispatch and the money item

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Step 3 of the technical review's fix order (`docs/reviews/2026-11-27-technical-review.md`, D-225), minus its
item 4 (which belongs to the dispatch milestone): the preview's fuel is the fuel to add (D-223, finding 4.1), the money
inputs are built one way with a test that New Flight and the planned flight agree (4.3), every money line carries its
working and reaches QML through one adapter (4.4), and the migration runner can rebuild a table (1.5) so that one
rebuild migration can turn the growing `CHECK` sets into lookup tables (2.1).

**Architecture:** `pricing.cpp` stays the only place that knows the quantities; it now derives the block time and the
fuel from raw facts in `PriceInput`, so the callers only copy fields. `MoneyLine` gains its quantities and rate, and
`workingText()` formats them. Migrations get a `rebuild` flag that turns foreign keys off around the transaction and
runs `PRAGMA foreign_key_check` before the commit. Migration 10 rebuilds `airplane`, `planned_flight` and `flight`.

**Tech stack:** C++20, SQLite C API (`src/sqlite_db.h`), GoogleTest, Qt 6 models.

**Spec:** the review's findings 1.5, 2.1, 4.1, 4.3, 4.4; D-223; `docs/dispatch.md` ("The working", "What the code
needs"); `docs/database.md`.

## Global constraints

- No warnings at `/W4 /permissive- /utf-8`, debug and release; qmllint reports only today's one info line.
- Money stays integer cents, each line rounded to $5 (D-080); a line's amount doesn't change in this step except fuel.
- Migrations are numbered, each in a transaction, tracked with `user_version`; tests build an empty database through
  every migration (CLAUDE.md, Database). Every foreign key column is indexed.
- Nothing already written to disk changes meaning: codes in `kind` and `return_reason` stay the same strings.
- Out of scope (left for later steps, say so in progress): 4.2/D-222's stored accepted lines, 4.8 (one `rates.yaml`
  loader), 4.9 (enums), 2.2 (the lease terms, with D-219's per-hour lease).

## Review focus

1. **A plan's ramp fuel below the fuel on record** (the airplane already holds enough): the fuel line is $0, so it
   is left out, but `fuelIncluded` is true and the total says "Total", not "Total + fuel". Test in Task 1.
2. **Migration 10 on Dave's real airline**, with settled flights with debriefs, reviews and money lines, and maybe a
   planned flight with a plan (and, in the test, a returned airplane): every row in every table survives, and the
   CASCADE children (cabins, holds, limits, phases, services, debrief rows) are all still there. Test in Task 4
   with a database filled at schema 9 and compared table by table.
3. **A rebuild migration that fails half-way** (a bad statement, or `foreign_key_check` finding a dangling row):
   nothing is changed, `user_version` stays, and foreign keys are back on for the rest of the session. Test in Task 3.
4. **A settled flight shown on Flights** (lines from the ledger, no working stored): the adapter gives an empty
   `working`, and nothing in QML breaks. Test in Task 2.
5. **A replay of an old settled flight** (its view from `flownFlightView`): the estimate's fuel uses that flight's
   stored `fuel_on_record_lb`, not today's airplane. Test in Task 1.

  has no rate, as ledger lines read back for Flights).
- `PlannedFlightDisplay` replaces `estimateLines` with `estimateIncome` and `estimateCosts` (the panel passed income
  as costs).

The lines' workings (quantities × rate [/ basis unit]):

| Line | Quantities | Rate | Basis, unit |
|---|---|---|---|
| Economy / business / first fares | passengers in the cabin, "passengers" | the fare | 1, "" |
| VIP fares | people, "passengers" | base + per nm × d | 1, "" |
| Charter | max(h, min hours), "h" | per hour | 1, "" |
| Cargo | cargo lb, "lb" | base + per nm × d (per 100 lb) | 100, "lb" |
| Fuel | lb charged, "lb" | price / 100 (dollars per 100 lb) | 100, "lb" |
| Landing fee | MLW lb, "lb MLW" | per 1,000 lb | 1000, "lb" |
| Gate, handling, GA services | none | the flat rate | 1, "departure" |
| ATC / navigation | distance, "nm" | per nm | 1, "nm" |
| Catering | people, "passengers" | per passenger (× VIP times) | 1, "" |
| Cargo handling | cargo lb, "lb" | per 1,000 lb | 1000, "lb" |
| Pilots | crew h, "h"; pilots, "pilots" | per hour | 1, "" |
| Flight attendants | crew h, "h"; attendants (× VIP times), "attendants" | per hour | 1, "" |
| Maintenance | crew h, "h" | per hour | 1, "" |

`workingText` format: quantities joined by " × ", each `formatNumber` for whole values else one decimal ("2.5 h",
"5,900 lb"); then " × $rate" with two decimals, more (up to 4) only when needed ("$0.4125"), whole dollars without
decimals ("$250"); then " / unit" or " / 1,000 lb" when `rateUnit` is set (basis shown when above 1). A flat line is
"$350 / departure". Display rounding of the hours doesn't change `cents`.
