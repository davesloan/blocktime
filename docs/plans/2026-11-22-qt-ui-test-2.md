# Qt UI Test 2 (Map and Data Screens) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, per CLAUDE.md / D-033; no
> subagent-driven development). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a side menu and two data screens to `blocktime-app`: a **Flights** screen that lists the flights in
the event log and draws the flown track on a dark map, and a **Fleet** screen that reads a table from SQLite. Dave
then judges UI test 2 and makes the Qt decision (`docs/qt-ui-test-context.md`).

**Architecture:**
- Reading flights from the log and reading the fleet from SQLite are plain C++ in `blocktime-core`, with GoogleTest
  tests. They know nothing about Qt (the context doc's rule: logic in plain C++, QML only displays).
- Thin Qt models (`FlightListModel`, `FleetTableModel`) wrap them for QML. QML draws the screens.
- The map is Qt Location's `MapView` with the `osm` plugin pointed at **CARTO Dark Matter** raster tiles (Dave's
  choice, 2026-11-22). The key comes from a local settings file, never from the repo. Without a key, the track is
  drawn on a plain dark background.
- `Main.qml` becomes a shell: a left side menu and a `StackLayout` of pages. Test 1's screen becomes the **Live**
  page, unchanged.

**Tech Stack:** as test 1 (C++20, MSVC /W4, CMake presets + Ninja, vcpkg, Qt 6.12.0 Qt Quick + Controls Basic),
plus **Qt Location / Qt Positioning** (installed), **Qt Network** (Location pulls it in), and **sqlite3** from vcpkg.

**Spec:** `docs/qt-ui-test-context.md` (UI test 2, pass criteria), D-050, D-051. Design for the fleet fields:
`docs/design.md` §3. Log format: `recorder/README.md` (Output), D-020, D-036.

## Choices made here (logged as Proposed in Task 7, except where Dave decided)

- **D-059, map tiles (Dave + Claude):** CARTO Dark Matter raster tiles through Qt Location's `osm` plugin (Dave).
  The key is `carto_key` in `%LOCALAPPDATA%\BlockTime\settings.json`. Tiles are cached in
  `%LOCALAPPDATA%\BlockTime\tiles\`, capped at 100 MB on disk, and files older than 30 days are deleted at startup
  (CARTO's caching limit). In-memory tile caches are capped small to protect the 100 MB budget. Alternatives:
  Stadia Smooth Dark (smaller free tier, needs an account), no tiles, MapLibre.
- **D-060, flights come from the event log:** the Flights screen rebuilds the flight list from the last 30 daily
  log files every time it loads. There's no separate flight database in this test. Each track keeps at most 2,000
  points (a point is kept only when it's 25 m or more from the last kept one, then evenly thinned). Distance and
  highest altitude are worked out from all the samples, before thinning. Why: the log is already the record of
  every flight (D-008), and this needs no new storage format. Alternative: a flights table in SQLite (that's the
  real app's job if Qt wins).
- **D-061, SQLite through vcpkg `sqlite3` in plain C++:** `FleetStore` in `blocktime-core` uses the sqlite3 C API
  directly, not Qt SQL. That keeps the airline data layer free of Qt and testable with GoogleTest. The database
  is `%LOCALAPPDATA%\BlockTime\blocktime.db`. The schema is a **test schema** (`PRAGMA user_version = 1`), seeded
  with sample airframes on first run. It's not the real airline schema. Alternative: Qt SQL's built-in `QSQLITE`
  driver (no new dependency, but it ties the data layer to Qt).
- **D-062, side menu:** a fixed left sidebar, 200 px wide, with three entries: **Live**, **Flights**, **Fleet**.
  The icons are glyphs from **Segoe Fluent Icons**, a Windows 11 system font, so there's nothing to bundle.

**Files:**

- Modify: `recorder/src/event_log.{h,cpp}` (gets `dailyLogFiles`), `recorder/src/open_flight.cpp` (uses it),
  `recorder/CMakeLists.txt` (core and tests)

**Interfaces:**
- Produces, in `event_log.h`: `std::vector<std::filesystem::path> dailyLogFiles(const std::filesystem::path& dir);`
  returns the `events-YYYY-MM-DD.jsonl` files, **oldest first**. It's the `isDailyLog` check moved out of
  `open_flight.cpp`, which now calls this and reverses the result.
- Produces, in `flight_history.h`:
  ```cpp
  struct TrackPoint { double lat = 0, lon = 0, altFt = 0; };
  enum class FlightEnd { Open, BlockIn, Interrupted };
  struct FlightRecord {
      std::string flightId, atcId, title;
      std::string outTime;                 // block_out data.time, as logged (ISO 8601 UTC)
      double outFuelLb = 0;
      FlightEnd end = FlightEnd::Open;
      std::string endTime;                 // block_in data.time, or the flight_interrupted line's ts; "" if Open
      std::string endReason;               // flight_interrupted reason, else ""
      std::optional<double> inFuelLb;      // block_in only
      std::optional<int> blockTimeS;       // block_in only
      double distanceNm = 0;               // over all samples, before thinning
      double maxAltFt = 0;                 // highest alt_ft (PLANE ALTITUDE) over all samples
      std::vector<TrackPoint> track;       // block_out position, telemetry, block_in position; thinned
  };
  inline constexpr std::size_t kFlightHistoryFiles = 30;
  inline constexpr std::size_t kMaxTrackPoints = 2000;
  inline constexpr double kTrackMinSpacingM = 25.0;
  // Newest flight first. Reads the last `maxFiles` daily logs, oldest to newest, as one stream.
  std::vector<FlightRecord> loadFlightHistory(const std::filesystem::path& dir,
                                              std::size_t maxFiles = kFlightHistoryFiles);
  ```
- Rules: a `block_out` line opens a flight. The `telemetry` lines after it (`lat`, `lon`, `alt_ft`) are its
  samples. A `block_in` or `flight_interrupted` line with the same `flight_id` closes it. A `block_out` while a
  flight is open closes the old one as Interrupted with reason `"unclosed"`. Lines that don't parse are skipped
  (D-036). Distance uses `distanceMeters` from `geo.h` (1 nm = 1,852 m).

- [ ] **Step 1: Write the failing tests** in `flight_history_test.cpp`, using the temp-dir fixture style of
  `open_flight_test.cpp` and log lines in the real format:
  - `CompleteFlight`: block_out (fuel 15315.6, atc_id N818SX), 3 telemetry, block_in (fuel 12141.0,
    block_time_s 1612) → one record. `end == BlockIn`, `blockTimeS == 1612`, `*inFuelLb == 12141.0`,
    `track.size() == 5`, `track.front()` is the block_out lat/lon, `track.back()` is the block_in lat/lon.
  - `NewestFirst`: two complete flights → `[0].flightId` is the later one.
  - `InterruptedFlight`: block_out, flight_interrupted reason `sim_stopped` → `end == Interrupted`,
    `endReason == "sim_stopped"`, `endTime` is the line's `ts`, `!blockTimeS`.
  - `OpenFlightAtEnd`: a block_out with nothing after it → `end == Open`.
  - `UnclosedFlightBeforeNewBlockOut`: block_out A, block_out B, block_in B → A is Interrupted with reason
    `"unclosed"`, B is BlockIn.
  - `CrossesUtcMidnight`: block_out and 2 telemetry in `events-2026-11-22.jsonl`, 2 telemetry and block_in in
    `events-2026-11-23.jsonl` → one flight with `track.size() == 6`.
  - `TornLineInsideFlight`: a half line (`{"ts":"2026-11-22T21:3`) between telemetry lines → the flight is whole,
    and the half line adds no point.
  - `TelemetryOutsideFlightIgnored`: telemetry before block_out and after block_in adds no points.
  - `DistanceAndMaxAltitude`: samples 1 nm apart in a straight line (0.0166667° of latitude) → `distanceNm` within
    0.01 of the expected total. `maxAltFt` is the highest sample.
  - `TrackThinnedTo2000`: 5,000 samples 100 m apart → `track.size() <= kMaxTrackPoints`, first and last kept,
    and `distanceNm` still counts all 5,000.
  - `CloseSamplesSkipped`: samples 5 m apart (taxi creep) → points under 25 m from the last kept are dropped.
  - `OnlyLastNFiles`: 3 daily files with `maxFiles = 2` → the oldest file's flight is missing.
